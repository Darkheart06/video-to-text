# Расшифровка записей

Приложение для macOS: берёт видео- или аудиозапись и отдаёт транскрипт с
таймкодами и разделением по спикерам, краткое саммари, бриф, список задач и
принятых решений.

**Всё считается на вашем компьютере.** Ни файл, ни текст никуда не отправляются:
распознавание — Whisper, спикеры — sherpa-onnx, саммари — языковая модель,
которую вы подключаете сами. Интернет нужен один раз, чтобы скачать модели.

🇬🇧 [In English](README.md)

![Окно приложения: идёт запись созвона, слева архив, ниже разобранная встреча](docs/screenshots/main.png)

Форматы: `mp4`, `mov`, `webm`, `mkv`, `avi`, `m4v` · `mp3`, `m4a`, `wav`, `flac`,
`ogg`, `opus`, `aac`.

---

## Установка

```bash
git clone https://github.com/Darkheart06/video-to-text.git
cd video-to-text
bash install.sh
```

Скрипт идёт по шагам и спрашивает перед каждой большой загрузкой: проверит
Python и ffmpeg, создаст окружение `.venv`, поставит библиотеки, скачает модели
для разделения по спикерам, поможет с языковой моделью и соберёт
`Расшифровка.app`.

Что нужно иметь заранее (скрипт подскажет, если чего-то нет):

| Компонент | Зачем | Как поставить |
|---|---|---|
| Python 3.9+ | всё приложение | обычно уже есть; иначе `brew install python@3.12` |
| ffmpeg | достать звук из видео | `brew install ffmpeg` |
| Языковая модель | саммари и бриф | см. следующий раздел |

Без языковой модели приложение работает — просто не делает саммари.

## Подключение языковой модели

Способа три, переключаются в «Настройках» → «Как подключена модель». Кнопка
«Проверить связь» там же реально дёргает модель и показывает её ответ.

### 1. Ollama — если не хочется разбираться

```bash
brew install --cask ollama
ollama pull gemma4:12b        # или gemma4:12b-mlx, см. ниже
```

Дальше ничего настраивать не нужно: приложение само находит Ollama на
`127.0.0.1:11434` и берёт лучшую из установленных моделей. В настройках можно
выбрать конкретную.

### 2. Файл .gguf на диске — если модель уже скачана

Скачиваете `.gguf` (например с Hugging Face), в настройках выбираете «Файл
.gguf на диске» и указываете путь. Никакого сервера запускать не надо.

Для этого нужна библиотека, которая умеет читать `.gguf` — `install.sh`
предлагает её поставить, но можно и вручную:

```bash
CMAKE_ARGS="-DGGML_METAL=on" .venv/bin/pip install llama-cpp-python
```

Собирается из исходников 3–10 минут и требует инструментов разработчика
(`xcode-select --install`). Флаг `-DGGML_METAL=on` включает счёт на видеоядре —
без него будет в разы медленнее.

Какой файл брать: ищите `Q4_K_M` в имени — это разумный компромисс между
качеством и размером. `Q5_K_M` чуть лучше и на четверть больше, `Q8_0` — почти
без потерь, но вдвое тяжелее.

### 3. Свой сервер с OpenAI API — если модель уже где-то крутится

Подходит LM Studio, `llama-server` из llama.cpp, Jan, LocalAI и любой другой
сервер с `/v1/chat/completions`. В настройках укажите адрес (у LM Studio это
`http://127.0.0.1:1234/v1`, у llama-server — `http://127.0.0.1:8080/v1`),
модель и, если нужен, ключ.

Тот же путь работает и с облачным сервисом, если вы сознательно хотите
отправлять расшифровку наружу — тогда впишите его адрес и ключ.

### Какую модель выбрать под свою память

Размер модели должен помещаться в оперативную память с запасом гигабайта в
три-четыре на систему и само приложение.

| Память Mac | Разумный выбор | Размер |
|---|---|---|
| 16 ГБ | `gemma4:e4b` | ~10 ГБ |
| 24 ГБ | `gemma4:12b` | ~8 ГБ |
| 32–48 ГБ | `gemma4:12b`, с запасом `gemma4:26b` | 8 / 19 ГБ |
| 64 ГБ и больше | `gemma4:26b` или `gemma4:31b` | 19 / 20 ГБ |

На Apple Silicon у моделей в Ollama есть варианты с суффиксом `-mlx`
(`gemma4:12b-mlx`) — то же самое, но собранное под Metal, работает заметно
быстрее. `install.sh` пробует сначала их.

## Сборка установщика (DMG)

Чтобы отдать приложение человеку, у которого нет ни Python, ни Homebrew:

```bash
bash packaging/make-dmg.sh
```

В папке `dist/` появится образ `Расшифровка-записей-1.0.0.dmg` — пара мегабайт.
Внутри «Установить Расшифровку.app»: он сам скачивает Python, ffmpeg и модели,
собирает приложение и кладёт его в «Программы». Терминал получателю не нужен.

Образ подписан самоподписанным сертификатом, поэтому на чужом Mac установщик
надо открыть **правой кнопкой → «Открыть»** — один раз. Это написано и в записке
внутри образа. Чтобы обойтись без этого, нужна платная подписка Apple Developer
и нотаризация.

| Файл | Отвечает за |
|---|---|
| `packaging/make-dmg.sh` | собирает образ целиком |
| `packaging/installer.applescript` | окно установщика с полосой прогресса |
| `packaging/install-payload.sh` | что именно происходит при установке |
| `packaging/dmg-readme.txt` | записка, которую видно при открытии образа |

Установленная копия живёт в `~/Library/Application Support/VideoToText`,
результаты — в `~/Documents/Расшифровка записей`, журнал установки — в
`~/Library/Logs/Расшифровка-установка.log`.

## Как пользоваться

Двойной клик по `Расшифровка.app` → выберите вверху, **что готовить из записи**,
и перетащите файл в окно (или нажмите «Выбрать запись»). Дальше видно прогресс по
этапам, а в конце — вкладки с разделами выбранного профиля и «Транскрипт».

Спикеров можно переименовать прямо в окне: впишите имена в поля внизу и нажмите
«Применить имена» — файлы транскрипта перезапишутся с новыми подписями.

### Что готовить из записи

Один и тот же транскрипт нужен для разного, поэтому наверху окна есть
переключатель профиля. Он же — в настройках и в ключе `--preset`.

| Профиль | Что получится |
|---|---|
| **Встреча или созвон** | саммари, бриф, решения, задачи, риски |
| **Смета по надиктованному** | таблица работ со ставками, количеством и итогом |
| **Голосовая заметка** | мысли по темам, задачи, названные цифры и списки |
| **Интервью с пользователем** | боли, дословные цитаты, выводы |
| **Свои правила** | всё, что опишете словами |

**Про смету.** Надиктуйте как есть: «демонтаж перегородки — двенадцать часов по
три тысячи, штробление — восемь часов по две с половиной». Модель разложит это по
колонкам, но умножать и складывать будет не она, а приложение: языковые модели
уверенно ошибаются в арифметике, и заметить это в готовом документе почти
невозможно. Рядом с `.summary.md` появится `.таблицы.csv` — открывается в Numbers
и Excel, числа в нём без валюты и пробелов, так что суммы можно считать дальше.

**Свои правила.** В настройках, раздел «Что готовить из записи»: в одном поле
пишете обычными словами, что нужно и чего делать нельзя, в другом — шаблон
документа. Каждый заголовок `##` в шаблоне становится вкладкой в окне и разделом
в файле. Колонки с названиями вроде «Количество» и «Ставка» приложение
перемножит само и допишет строку «Итого» — в любом профиле, не только в смете.

![Профиль «Смета»: таблица работ с посчитанным итогом](docs/screenshots/estimate.png)

### Запись созвона

Кнопка «Начать запись созвона» — или приложение само предложит, когда заметит,
что микрофон занят. macOS попросит разрешение на запись экрана: именно оно даёт
доступ к системному звуку. Кнопка в приложении открывает нужный раздел настроек
сразу, руками искать не надо.

Свой микрофон и системный звук пишутся раздельно, поэтому «я» и «собеседник» не
путаются между собой.

### Кто говорит на созвоне

Во время разговора приложение различает только «Я» и «Собеседник»: дорожки дают
ровно это — мой микрофон и всё остальное. Когда запись останавливается,
системная дорожка отдельно разбирается по голосам, и в готовом транскрипте
появляются «Собеседник 1», «Собеседник 2» и так далее. Своя дорожка в разбор не
идёт — мой голос там и так известен, и он только мешал бы кластеризации.

Занимает это около двух минут на час разговора. Отключается галочкой
«Различать собеседников по голосам» в настройках.

### Архив записей

Слева — список всего, что уже разобрано: и файлы, и записанные созвоны. Клик по
записи разворачивает её обратно в то же окно с вкладками, что и сразу после
обработки, — искать файлы в папке не нужно. Поиск сверху ищет по названию, а с
трёх букв — и внутри самих расшифровок, так что «где мы обсуждали смету» находится
за секунду. Крестик убирает запись со всеми файлами в Корзину (спрашивает
подтверждение), кнопка «Архив» в шапке прячет панель.

Список строится по файлам `.result.json` в папке результатов, отдельной базы
нет. Поэтому архив переживает переустановку приложения: скопировали папку —
записи снова на месте. Имена спикеров можно поправить и у старой записи —
транскрипт и субтитры перепишутся.

### Копирование текста

Текст расшифровки и саммари выделяется мышью и копируется как обычно — Cmd+C.
Кнопка «Копировать» справа над текстом кладёт в буфер всю открытую вкладку
целиком: раздел саммари как есть или транскрипт с таймкодами. Cmd+A выделяет
текст открытой вкладки, а не всё окно.

Кнопки, вкладки и список слева от выделения защищены — иначе при попытке
выделить абзац «красится» пол-окна.

### Из терминала

```bash
./run.sh встреча.mp4                          # всё по умолчанию
./run.sh *.mov --speakers 3                   # знаем, что говорящих трое
./run.sh лекция.m4a --no-speakers             # один голос, разделение не нужно
./run.sh интервью.mp4 --language ru --model large-v3
./run.sh запись.webm --no-summary             # только транскрипт
./run.sh смета.m4a --preset estimate          # таблица работ с итогом
./run.sh заметка.m4a --preset note            # разложить надиктованное по полочкам

./run.sh --check-llm                          # проверить связь с моделью
./run.sh встреча.mp4 --ollama-model gemma4:12b-mlx
./run.sh встреча.mp4 --gguf ~/Models/gemma-4-12b-Q4_K_M.gguf
./run.sh встреча.mp4 --api http://127.0.0.1:1234/v1
```

## Что появляется на выходе

Для файла `встреча.mp4` в папке `~/Documents/Расшифровка записей`:

| Файл | Что внутри |
|---|---|
| `встреча.summary.md` | разделы выбранного профиля: саммари, бриф, задачи… |
| `встреча.таблицы.csv` | таблицы с пересчитанными суммами — если они были |
| `встреча.transcript.md` | транскрипт с таймкодами и спикерами |
| `встреча.transcript.txt` | то же простым текстом |
| `встреча.subtitles.srt` | субтитры |
| `встреча.result.json` | всё вместе для другой обработки и для архива в окне |

## Настройки

Кнопка «Настройки» в окне или файл `config.json` рядом с проектом.

**Язык.** `auto` определяет сам. Если язык записи известен — укажите его, будет
точнее и быстрее.

**Модель Whisper.** `large-v3-turbo` — разумный выбор по умолчанию. `small` и
`base` заметно быстрее, но ошибаются на именах и терминах.

**Сколько спикеров.** `0` — определить автоматически. Если точно знаете число,
поставьте его: результат ощутимо чище.

**Порог разделения.** Меньше — больше спикеров. Если два голоса склеились в
одного, снизьте до `0.5`; если один человек разбился на несколько — поднимите до
`0.7`. После разделения приложение всё равно сверяет голоса между собой и
склеивает кластеры, которые оказались одним человеком (`speaker_merge_similarity`
в `config.json`, по умолчанию `0.78`; `1.0` — не сверять вовсе). На настоящей
получасовой встрече это убрало 28 «спикеров» до семи.

**Что готовить из записи.** Профиль задаёт правила для модели и шаблон
документа — см. раздел выше. «Свои правила» позволяют написать своё, без
программирования.

**Размер контекста.** Сколько текста модель держит за раз. Больше — связнее
итоговый бриф, но нужнее память. 32768 подходит почти всем.

## Сколько это занимает времени

Ориентир для часовой записи на Apple Silicon: распознавание 3–8 минут на
`large-v3-turbo` через MLX, разделение по спикерам 1–3 минуты, саммари 1–4
минуты. На Intel-маках заметно дольше — там имеет смысл модель `medium`.

Первый запуск дольше остальных: модель Whisper (около 1.5 ГБ) скачивается один
раз и потом лежит в `~/.cache/huggingface`.

## Если что-то не работает

**«ffmpeg не найден»** — `brew install ffmpeg`.

**«Ollama не отвечает»** — запустите приложение Ollama (или `ollama serve`).
Проверить: `curl http://127.0.0.1:11434/api/tags`.

**«Сервер модели не отвечает»** — адрес должен заканчиваться на `/v1`, и сервер
должен быть запущен. Проверить: `curl http://127.0.0.1:1234/v1/models`.

**Файл .gguf не открывается** — либо не установлена `llama-cpp-python`, либо
модели не хватает памяти: уменьшите размер контекста или возьмите файл с более
сильным сжатием (`Q4_K_M` вместо `Q8_0`).

**Окно не открывается** — посмотрите ошибку в терминале: `./run.sh` без
аргументов. Всё то же самое доступно консольной командой с файлом.

**Спикеры определились неверно** — задайте точное число спикеров или подвиньте
порог разделения. На записях, где говорят одновременно или звук идёт из одной
дальней точки комнаты, диаризация ошибается чаще.

**Саммари получилось поверхностным** — возьмите модель побольше и выберите её в
настройках.

## Как устроено

```
файл → ffmpeg (моно 16 кГц) → Whisper (текст + таймкоды слов)
                            → sherpa-onnx (кто когда говорил)
                            → сведение по словам → реплики
                            → языковая модель: разбор по частям → итоговый бриф
                            → .md / .csv / .txt / .srt / .json
```

| Файл | Отвечает за |
|---|---|
| `app/media.py` | проверка файла, извлечение звука, нарезка на куски |
| `app/asr.py` | распознавание (MLX или faster-whisper) |
| `app/diarize.py` | разделение по спикерам, сведение голосов одного человека |
| `app/merge.py` | кто произнёс какую фразу, сборка реплик |
| `app/cleanup.py` | чистка от эканья и слов-паразитов |
| `app/llm.py` | три способа подключить языковую модель |
| `app/presets.py` | профили: что именно готовим из записи |
| `app/summarize.py` | промпты, разбор длинных записей по частям |
| `app/compute.py` | пересчёт таблиц: арифметика мимо модели |
| `app/record.py` | запись созвона, две дорожки, заметки по ходу |
| `app/library.py` | архив разобранных записей |
| `app/render.py` | markdown, csv, srt, json |
| `app/pipeline.py` | порядок этапов, прогресс, отмена |
| `app/main.py` | окно и мост в интерфейс |
| `app/cli.py` | консольная версия |
| `capture/main.swift` | помощник захвата звука на ScreenCaptureKit |
| `tools/selftest.py` | сквозная проверка пайплайна |
| `tools/uicheck.py` | проверка интерфейса в браузере |

Почему именно так — [docs/architecture.ru.md](docs/architecture.ru.md).
